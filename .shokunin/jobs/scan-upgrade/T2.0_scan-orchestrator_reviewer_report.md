## Skills invoked

- `shokunin-review`: no reinvented types, no redeclared T1.1 errors, no
  try/catch swallowing transport errors, no `any`, no duplication with
  `rewriteAttributionSrc`. One non-blocking style note: `buildSubmitOptions`
  and `buildPollOptions` repeat the same `...(x === undefined ? {} : { x })`
  conditional-spread idiom for `baseUrl`/`timeoutMs` — mirrors the existing
  idiom already used in `scanner-client.ts`'s `fetchScan`, so it is consistent
  with codebase convention rather than a new pattern; extracting a shared
  helper for two call sites would be the YAGNI trade in the other direction.
  Not blocking. `@filemeta` on `scan.ts` is accurate and complete.
- `code-review`: no correctness bugs found. `isTerminalStatus` gate is
  correct and exhaustive (`done`/`failed` are the only terminal values per
  `SCAN_STATUSES`); the `onProgress` type cast
  (`as NonNullable<PollScanOptions['onProgress']>`) is a deliberate, commented,
  sound narrowing — `pollScan` only ever invokes progress callbacks with a
  runtime-validated `ScanProgressStep` (enforced by `requireEnum` in
  `parseOptionalProgress`, scanner-client.ts), so the wider `PollScanOptions`
  parameter type is never actually violated at runtime. No cross-file
  breakage: `scan.ts` is new, has no existing callers yet (cli.ts wiring is
  T2.1, out of scope here and confirmed untouched).
