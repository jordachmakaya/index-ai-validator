### 8. Craft judgment (shokunin-review lens)

**`formatAjvErrors` opt-in extension** (`appendMissingPropertyToRequiredPath`):
reasonable and minimal. It reuses the single shared formatter instead of
writing a parallel one for `validateScanResult`, defaults to `undefined` so
the two existing callers (`validateManifestSchema`, `validateGraphSchema`)
are provably unaffected (confirmed by reading their call sites at lines
280 and 296 — both call `formatAjvErrors(validate.errors)` with no second
argument), and the new logic is 6 lines gated behind one boolean. This is the
right size for the problem — a bespoke wrapper function or a second AJV
error-formatting utility would have been unnecessary duplication. No
simpler alternative comes to mind that wouldn't touch the two pre-existing
callers' path semantics.

**5-position tuple schema for `dimensions`** (`items` as an array of 5
`const`-pinned position schemas + `minItems`/`maxItems`/`additionalItems: false`):
judged appropriate, not over-engineered. The contract text is explicit —
"TOUJOURS les 5, ordre fixe" (`CONTRACT_SCANNER.md §6`) — order is a
contractual invariant, not an implementation detail. A weaker schema
(`minItems`/`maxItems: 5` + `enum` on `key` + no positional pinning) would
let duplicate or out-of-order keys slip through structurally undetected,
silently violating the contract. The tuple form directly encodes the
invariant the contract states, at the cost of 5 near-identical schema blocks
in the JSON file — a reasonable, explicit trade, not speculative
abstraction. **No change requested.**

**Non-blocking observation**: the 5 tuple blocks in
`scan-result.schema.json` are structurally identical except for one `const`
value, which is mild duplication in the JSON schema itself (not in the TS
code, and JSON schema has no way to template this without draft 2019/2020
`$defs` + `unevaluatedItems`, which AJV 8's default draft-07 mode doesn't
support). Not worth blocking on — vendored JSON schemas commonly carry this
kind of repetition, and introducing `$defs` here for 5 near-identical blocks
would be the over-engineering the coder correctly avoided.
