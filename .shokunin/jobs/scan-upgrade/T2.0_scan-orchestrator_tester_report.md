## 8 test cases written (mapped to JOB.md's minimum list)

1. `submitScan` → `queued`, `pollScan` → `done`: asserts `pollScan` called
   once with the `scanId`, `outcome.status` is the exact object `pollScan`
   resolved (`toBe`), `meta.links.audit` still `src=cli-json`,
   `auditLinks.html`/`auditLinks.terminal` contain `src=cli-report` /
   `src=cli-terminal` and the preserved `scanId`.
2. `submitScan` → `done` directly (cache): asserts `pollScan` is **never
   called** (`not.toHaveBeenCalled()`), same resolution shape as case 1.
3. `submitScan` → `queued`, `pollScan` → `failed` (`failureReason:
   "SCAN-002"`): asserts rejection is `instanceof ScanFailedError`,
   `error.code === "SCAN-002"`, message contains `"SCAN-002"` and is not the
   generic string `"Scan failed."`.
4. `submitScan` → `failed` directly (cache): same `ScanFailedError`
   assertions as case 3, plus `pollScan` never called.
5. `submitScan` rejects with a real `ScanRequestError` instance: asserts
   `scanUrl(...)` rejects with **the exact same instance** (`rejects.toBe`),
   not caught/wrapped; `pollScan` never called.
6. `pollScan` rejects with a real `ScanTimeoutError` instance: asserts
   `scanUrl(...)` rejects with that exact instance, uncaught/untransformed.
7. `options.onProgress` forwarding: passes a `vi.fn()`, asserts the exact
   same function reference is the `onProgress` field `pollScan` received
   (`toBe` on the mock call's second argument) — no wrapper.
8. `options.baseUrl`/`timeoutMs`/`intervalMs`/`budgetMs` forwarding: asserts
   `submitScan` received `baseUrl`/`timeoutMs` and `pollScan` received all
   four, via `expect.objectContaining` on the mocks' call arguments.

No HTTP server anywhere in this file — `client/scanner-client` is replaced
entirely via `vi.mock(..., async () => ({ ...actual, submitScan: vi.fn(),
pollScan: vi.fn() }))`, preserving the real error classes (`ScanRequestError`,
`ScanTimeoutError`, etc.) so instances constructed in tests are genuine.
