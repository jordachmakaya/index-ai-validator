## API contract assumed by the tests (for the Coder job)

Since `client/scanner-client.ts` does not exist, this Tester job had to fix
the exact surface the tests import, per `IMPLEMENTATION_PLAN.md` §T1.1 and
`CONTRACT_SCANNER.md`:

- `submitScan(url: string, options?: { baseUrl?: string; timeoutMs?: number }): Promise<ScanStatus>`
- `pollScan(scanId: string, options?: { baseUrl?: string; timeoutMs?: number; intervalMs?: number; budgetMs?: number; onProgress?: (progress: { currentStep: string }) => void }): Promise<ScanStatus>`
- `type ScanStatus` mirrors `CONTRACT_SCANNER.md §5` exactly (`scanId`,
  `status`, `submittedAt`, `completedAt`, `progress?`, `failureReason?`,
  `result?: ScanResult` reusing `ScanResult` from `../schemas`, `meta`).
- Typed errors, one class per contractual failure mode: `ScanRequestError`
  (400 / SCAN-001-003), `ScanNotFoundError` (404), `ScanExpiredError` (410,
  message must suggest a re-scan — the client adds this, not just forwards
  the server message), `ScanRateLimitError` (429, retry exhausted),
  `ScanServerError` (500), `ScanTimeoutError` (90s poll budget exceeded),
  `ScanResultSchemaError` (done result fails `validateScanResult` — e.g.
  incompatible major `schemaVersion` — kept distinct from the network error
  classes above).
- `baseUrl` option overrides the default `INDEX_AI_SCANNER_URL` base so
  tests never touch the real network — every test points it at a local
  ephemeral `node:http` server.

## 15 test cases written

`submitScan` (5):
1. `resolves with the typed queued ScanStatus on a 202`
2. `treats a 200 cache response identically to a 202, reading scanId/status the same way`
3. `always sends { url, channel: "cli" } in the request body` — asserts on
   the method/path/body the mock server actually received
4. `rejects with a typed ScanRequestError carrying the exact contract message on a 400`
5. `retries once after a 429 with Retry-After and succeeds if the retry lands`
   — Vitest fake timers advance past the `Retry-After` delay instead of a
   real sleep

`pollScan` (10):
6. `polls running with progress.currentStep then resolves on done, stopping immediately at the terminal state`
   — asserts `onProgress` fired exactly once for the `running` step, and
   exactly 2 requests total (no extra poll after `done`)
7. `resolves immediately on a failed terminal state without any further poll`
   — asserts `failureReason: 'SCAN-002'` and exactly 1 request
8. `fails cleanly with ScanRateLimitError when the retry also gets a 429 (no infinite loop, no multi-attempt backoff)`
   — fake timers advance past the retry delay; asserts exactly 2 requests
   (1 original + 1 retry, never more)
9. `rejects immediately with ScanNotFoundError on a 404, without retrying`
10. `rejects immediately with ScanExpiredError suggesting a re-scan on a 410`
    — the fixture's server message deliberately omits "re-scan" to prove
    the client itself appends the suggestion
11. `rejects immediately with ScanServerError on a 500`
12. `gives up after the 90s server-side polling budget without looping forever`
    — mock server always answers `running`; uses `vi.useFakeTimers()` +
    `vi.advanceTimersByTimeAsync(95_000)`, never a real 90s sleep
13. `validates a done result against the vendored ScanResult schema and exposes it typed as-is`
    — reuses `validateScanResult`/`ScanResult` from T1.0's `schemas.ts`,
    real `CONTRACT_SCANNER.md §9` done fixture
14. `rejects a done result with an incompatible major schema version with an explicit error, never a silent partial parse`
    — `schemaVersion: '2.0'` vs vendored `'1.0'`; asserts `ScanResultSchemaError`
    and explicitly asserts it is **not** `ScanServerError`/`ScanRequestError`
15. `tolerates an unknown additive field on the done result without raising an error`

Local `node:http` mock server per test, same pattern as `http.test.ts`
(`startServer`/`closeServer`/`isAddressInfo` helpers duplicated locally in
this file — not imported from `http.test.ts`, per the job boundary). Every
server is closed in a `finally` block. No test calls the public internet.
